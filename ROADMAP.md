# Roadmap: a release train through the automation

Date: 2026-08-28

Status: proposed. Orders the next go-unifi releases and the
terraform-provider-unifi releases that consume them. It names the tooling
each release must run through, the gaps already known in that tooling, and
what each release measures.

## Aim

Ship several releases in a row using only the repositories' own automation:
the controller image pipeline in unifi-containers, the capture, generation,
compatibility and release workflows here, and the provider's new-controller
playbook. The first release is a controller bump and nothing else, so the
controller-upgrade machinery is exercised in isolation and every place it
needs a human is recorded. The provider then does the same. The releases
after that carry what the provider needs, in the order its own release
train needs them.

Where the tooling fails, the fix is to the tooling, in the same release.
Where it has a gap, the gap is closed with the smallest change that reuses
what already exists. Nothing is hand-made: no hand-edited generated code, no
hand-picked controller version, no hand-added field, no hand-cut tag while
an automated path exists.

## Starting position

- go-unifi v1.105.1 is locked to UniFi Network 10.4.57
  (`schemas/capture.lock.json`). Generation from the lock is byte-identical
  on a clean tree. `cmd/apidiff` reports Go-API and wire-surface deltas
  against the latest tag and gates `auto-release`.
- The canonical repository is `git.octanix.dev/infra/go-unifi`. Review and
  merge happen there. `github.com/jamesbraid/go-unifi` is a one-way mirror
  and is where tags are minted (`auto-release`, which runs only on GitHub)
  and releases published (`release`, goreleaser). `upstream`
  (ubiquiti-community) is never touched.
- unifi-containers publishes `ghcr.io/jamesbraid/unifi-network:<ver>-sim`
  from a pinned package URL. Its updater (Woodpecker `update.yml`, cron or
  manual) selects the next stable from the Ubiquiti apt stable dist, opens a
  bump PR, and on merge `tag.yml` mints `v<ver>-1`, `sync-tag.yml` syncs the
  mirror, and GitHub `network-release.yml` builds, health-gates and
  publishes. `docs/sim-keys/<ver>.txt` is regenerated by the updater.
- terraform-provider-unifi v0.105.0 consumes go-unifi through a `replace`
  onto the fork at v1.105.1. Its acceptance suite runs against
  `unifi-network:10.4.57-sim` and the unifi-emu herder v0.5.1. Its
  `development/new-controller.md` is the playbook a controller bump follows.
- Forgejo PR #8 (branch `emdash/go-unifi-roadmap-eliiz`) holds the masked
  updates for settings, WireGuard peers, BGP, power supervisors and sites,
  plus the site-command path fix. It is not part of the first release and
  waits for the bump tag.
- Forgejo PR #5 is the capture workflow's PR for 10.4.57, left open after
  that lock landed by another route. The workflow reuses its branch
  (`schema-update`), so the next capture updates this PR in place.

## Principles

1. One controller train per release, chosen by the unifi-containers updater
   from the apt stable dist. Nobody types a version.
2. A field exists in the SDK only if the locked controller's own definitions
   carry it, or a probe measured the controller serving it and recorded the
   build it measured. The provider never adds a field the SDK struct does
   not carry.
3. Review and merge on Forgejo. Tags and releases on the fork, by the
   workflows, after review. The mirror is the only writer to GitHub.
4. Every release records what the tooling could not do alone: each human
   decision, each intervention, and the wall-clock of each step. Those
   numbers are the release's result as much as the artifact is.
5. A pure release changes one thing. The controller-bump releases carry the
   lock, what the capture regenerates from it, and what the drift probe
   measures against it. Nothing else.

## Release train

### R1 — go-unifi v1.106.0: controller bump only

Objective: prove the controller-upgrade machinery end to end, from a new
controller image to a published SDK release, with no other change in the
diff.

Steps, each through its tool:

1. unifi-containers: trigger the Woodpecker updater (`update.yml`, stable
   channel). It opens `network: bump to <ver>`, regenerates
   `docs/sim-keys/<ver>.txt`, and checks run (`updater-tests`,
   `verify-pins`). Review, merge. `tag.yml` mints `v<ver>-1`, the mirror
   syncs, GitHub builds and publishes `<ver>-sim` and moves `sim`.
   Gate: `docker pull ghcr.io/jamesbraid/unifi-network:<ver>-sim` and the
   image's own healthcheck passes. That healthcheck now clears three
   stages, not a login alone: a login, then the v2 firewall-policies
   surface answering while zone-based-firewall defaults materialize, then
   the full seeded device fleet. A consumer can read the same verdict from
   `GET :9099/readyz` where Docker health is not visible. Nothing should
   poll the login endpoint itself; the controller rate-limits it globally
   with a Retry-After of up to an hour.
2. go-unifi: dispatch the capture workflow on Forgejo with the artifact URL
   unifi-containers pinned (`network/Dockerfile` `PKGURL`), so the SDK and
   the test image are built from the same bytes. It proposes the lock,
   regenerates, records `GENERATED_SHA256`, runs `apidiff`, and opens or
   updates the schema PR as `infra-ci-bot`.
3. On the schema PR: `ci` (lock verification, byte-identical regeneration,
   lint, tests) and `integration` (pulls `<ver>-sim` from `schemas/VERSION`,
   runs the suite and the v2 drift probe). Drift findings are measured
   definitions and go to `overrides/resources/` with the build recorded;
   fields the regeneration adds to `Network` are classified by the field
   probe against the same controller, and only a field measured as
   persisted is wired into an encoder;
   ownership pins are re-measured where the controller changed. Review the
   lock, the API diff, and the integration evidence. Merge.
4. Mirror sync carries `main` to the fork. `auto-release` runs `apidiff`
   against v1.105.1 and tags v1.106.0, unless the diff is breaking, in which
   case it refuses and the tag is a recorded human decision (still a
   documented minor, per COMPATIBILITY.md). `release` publishes the
   goreleaser notes naming the controller train.

Gate: the tag exists on the fork; `go get` from the public proxy resolves
it cold; the release notes name the new train; the diff between v1.105.1
and v1.106.0 contains the lock, generated output, `overrides/resources/`
measurements, and workflow or tooling fixes made during this release, and
nothing else.

Not in this release: PR #8, any client change, any override that is not a
probe measurement, any re-evaluation of fields the provider wants.

### R1' — terraform-provider-unifi v0.106.0: controller bump only

Objective: prove the provider's playbook the same way, against the same
controller, with the SDK tag as its only input.

Run `development/new-controller.md` verbatim from the v1.106.0 tag: bump
the `replace`, `go generate` (bootstraps regenerate from the new SDK
commit), adjust policy only where a bootstrap changed shape, regenerate,
update descriptors and the schema snapshot, run the conformance suites and
the acceptance suite against `<ver>-sim`. Review and merge on Forgejo;
tag and release on the fork.

The provider can dry-run the playbook against the schema PR's branch before
the tag exists, which is when tooling failures should surface. Any failure
found there is fixed in go-unifi before v1.106.0 is cut, not worked around
in the provider.

Gate: `go generate ./...` produces no diff against the committed tree; the
schema snapshot diff is reviewed and committed with the changes that caused
it; acceptance is green on the new image; the release carries the bump and
the tooling fixes it needed, and nothing else.

### R2 — go-unifi v1.107.0: masked updates for the whole-object endpoints

Objective: land what the provider's surface migrations and settings work
are gated on.

Content: Forgejo PR #8, rebased onto the v1.106.0 main. `UpdateSettingFields`,
`UpdateWireGuardPeerFields`, `UpdateBGPConfigFields`,
`UpdatePowerSupervisorFields`, `UpdateSiteFields`, the raw-JSON overlay they
share, and the site-command path fix. The read, list and delete calls the
provider's Read and Delete closures bind to already exist for all five
types (`GetBGPConfig`, `ListWireGuardPeers`/`GetWireGuardPeer`,
`GetPowerSupervisor`, `GetSiteByName`, and the matching deletes; the site
delete's path is fixed in the same PR).

Gate: the PR's own tests (unit, and the integration tests that pin the
measured merge and refusal semantics) green on Forgejo; `apidiff` additive
against v1.106.0; tag by `auto-release`.

### R2' — the provider's own train

The provider ships three releases after its bump, and only the middle one
consumes R2:

- v0.107.0: upstream triage, validators derived from the SDK's exported
  enum facts, defect fixes, test infrastructure. Consumes v1.106.0.
- v0.108.0: the seven hand-written surfaces onto the kit, `unifi_setting`
  as a composite of per-section specs, and the settings sections. This is
  the release that needs R2's masked updates.
- v0.109.0: `unifi_nat` and content filtering. Consumes v1.106.0; the SDK
  already carries their full CRUD.

### R3 — go-unifi v1.108.0: facts the provider now derives by convention

Objective: turn the naming conventions the provider's generator depends on
into declared contracts, and derive from the controller what is today
hand-maintained. Each item is generated from data the pipeline already has.

- Enum, range and length facts keyed by Go type and wire name
  (`FieldEnumValues`, `FieldNumericRanges`, `FieldLengths`), emitted beside
  the existing per-field variables from the same extractor. A lookup table
  is a contract; a name-mangling scheme is a convention.
- The wire fields each Network purpose encoder emits, exported as a
  function, computed by running the encoder rather than declared. The
  provider replaces its hand-declared unwritable-wire lists with it.
- `apidiff` extends its wire baseline to those per-purpose sets, so a change
  in what a purpose writes is reported like any other wire-surface change.
- The hand-maintained settings sections (`ipsec`, `global_network`,
  `provider_capabilities`) violate principle 2. The controller serves them,
  so they are measurable: extend the existing drift probe, which already
  produces measured definitions for v2 objects the jar does not describe,
  to `get/setting` sections absent from `Setting.json`. The measured
  definitions replace the hand-written structs. Until then the provider does
  not add those sections.

Gate: additive `apidiff`; every new exported fact has a test that derives
it independently from the same source.

### Later

A second controller bump, run exactly as R1/R1' but against a provider with
no hand-written surfaces, to compare the numbers. A controller version that
defines a field the provider wanted (per-SSID band steering, for example)
rides in on such a bump as ordinary policy work.

## Tooling gaps to close on the way

Known before R1 starts. Each is fixed in the release that first hits it,
with the smallest change that reuses what exists.

1. go-unifi has no mirror-sync trigger. unifi-containers documents its
   mirror as manual-sync and triggers the sync from CI (`sync-tag.yml`,
   `scripts/sync-mirror.py`). If go-unifi's mirror is the same, a merge on
   Forgejo never reaches the fork and `auto-release` never fires. Fix: a
   Woodpecker pipeline on push to `main` (and tag) that calls the same
   sync, copied from unifi-containers. R1 step 4 measures whether this is
   needed.
2. Tags exist only on the fork. Forgejo clones carry no `v*` tags, so
   `apidiff` on Forgejo CI has no baseline. Fix: the workflow fetches tags
   from the fork's public URL when the local repository has none. One step,
   no new mirror direction.
3. The capture workflow takes the artifact URL, build identity and Network
   version as typed inputs. The build identity is inside the artifact
   (`schema-capture` already extracts the jar to compute snapshots), and
   the version is a check, not an input. Fix: `schema-capture` reads both
   from the artifact and the workflow requires only the URL, which comes
   from unifi-containers' `PKGURL`.
4. The provider's `docker-compose.yaml` pins `unifi-network:10.4.57-sim` as
   a literal while its playbook says the default tracks the SDK. Fix: the
   acceptance harness derives the default image from `unifi.UnifiVersion`,
   so bumping the `replace` moves the image. Provider-owned; surfaces in
   R1'.
5. Forgejo Actions run state is invisible to anything without a
   `jamesb`-scoped token (tea keeps its token in the keyring; the
   unauthenticated API answers 404 on private repositories). Working
   autonomously through the forge needs a read-scoped token in 1Password
   under the usual naming. A decision, not code.
6. The unifi-emu herder pin (v0.5.1 in both repositories' CI) is only known
   to be right for 10.4.57. The SDK integration suite on the schema PR
   adopts devices and is the measurement; a failure there is a herder
   release before the tag, not a skip.

## Measurements

Recorded per release, in the release PR and the release notes:

- Wall-clock per step, from trigger to gate.
- Human decisions: count and content. For R1 the expected set is: merge the
  unifi-containers bump, merge the schema PR, accept or refuse a breaking
  `apidiff` result. For R1': merge, plus each policy decision where a
  bootstrap changed shape.
- Interventions: every place the tooling stopped and a person or agent did
  something by hand. Each becomes a fix commit in the same release, or a
  numbered gap above.
- The evidence the gates rest on: `apidiff` summary, drift-probe findings,
  integration and acceptance results, schema-snapshot diff size, number of
  surfaces whose bootstrap changed.

## Ownership boundary

go-unifi owns endpoint paths and verbs, masked-write and read-overlay
semantics, the purpose encoders, enum/range/pattern facts, and decoding the
controller's validation error. terraform-provider-unifi owns what a zero
read means, plan modifiers and defaults, derived attributes, write-only
stash hooks, import routing and identity, and the mapping of encoder slots
to attributes. Neither layer adds a field the layer below does not carry.

## Open decisions

- Whether `auto-release` should refuse or accept a breaking `apidiff` on
  the R1 bump is decided when the diff exists, not before. COMPATIBILITY.md
  already says a controller-forced break is a documented minor.
- Gap 5 (a read-scoped forge token for automation) is a policy decision.
